# Datasets: what we used, what it showed, and what it does and does not prove

**Read this first.** Every evaluation dataset here is **synthetic and self-authored** *except section 9*,
which uses public benchmarks with real human gold labels. Section 9 materially contradicts the synthetic
results and should be weighted above them.

The rest of this warning still applies to sections 4-7. There is no
public benchmark for this task, so we wrote both the inputs and the expected answers. That is sound for
the two jobs we actually needed — verifying wire compatibility, and comparing two systems on identical
inputs — and it is *not* an unbiased measurement of absolute accuracy. Quantified at the bottom.

No real customer data was used anywhere. The brief required synthetic states only, and the evaluation
states are generated or hand-written fiction.

---

## 1. `tests/fixtures/golden/` — 15 live responses from the real Jev

**What.** Real request/response pairs recorded from `https://api.typesafe.ai/v1/systemone` with a real
API key: one per question type, plus criteria variants, every state form, structured instructions, and
five error cases. Recorded by `scripts/record_golden.py`, re-runnable.

**What it showed.** The published docs are wrong or silent in several places. `release_date` is an ISO-8601
timestamp, not `YYYY-MM-DD`. A missing API key returns **403**, an invalid one **401**, though the docs
table lists only 401. An unknown question `type` returns **400** with a generic message while a *missing*
`type` returns **422** with `union_tag_not_found`. Size-ceiling violations return `400` with a bare
**string** `detail`, not the object form. Noul answers carry no `confidence` field.

**Why this was the right dataset.** It is the actual contract. Every one of those seven findings would
have been a compatibility bug had we implemented from the documentation. Contract tests diff our
responses against these field by field.

**Limits.** 15 cases is enough for shape, not for exhaustive edge coverage. Re-record after any TypeSafe
release: `test_the_published_spec_still_only_has_the_two_routes` fails loudly if their API grows.

## 2. `tests/fixtures/jev_confidence_samples.json` — 66 live Jev answers

**What.** 66 choice and score answers from the real Jev across K=2..10, over five states chosen to give a
spread of distribution shapes (confident, split, bimodal, flat).

**What it showed.** The confidence formula in the build brief (`1 - H(p)/ln K`) is **not** what Jev
computes. Choice uses `(K*p_max - 1)/(K - 1)`; score uses an ordinal statistic,
`1 - E|level - mode| / D_K`. Mean absolute error of our implementation against these 66: **0.0085**,
and the residual is fully explained by Jev rounding its output to two decimals.

**Why this was the right dataset.** The formula is undocumented — the docs render an interactive widget
instead of stating it. Only observed input/output pairs could recover it. K was deliberately swept
because a nominal and an ordinal statistic agree when K=2 and only diverge above it; a 2-option-only
sample would have "confirmed" the wrong formula.

**Limits.** Fitted on rounded outputs, so we can recover the formula but not the last decimal.

## 3. `tests/fixtures/typesafe_openapi.json` — the published spec

Fetched from `https://api.typesafe.ai/openapi.json`. Used to assert our generated OpenAPI carries the
same properties and the same `required` sets. Caught one real bug: we had published answer `type` as
optional because our model gave it a default.

## 4. `tests/fixtures/eval_cases.py` — the 15-question baseline pack

**What.** Vendored verbatim from `longest.py`, the run that produced the original 14/15. Synthetic support
threads generated by `build_thread`, which pads a neutral message pool to a target token count and inserts
decisive facts at fixed positions. Four categories: buried fact at 500-6500 tokens, multi-question over
one state, refund-policy rule application, and a sales-talk distractor.

**What it showed.** so1 scores **14/15**, reproducing the original direct-endpoint run exactly, including
the same single miss (`rules/annual-3-exports`).

**Why this was the right dataset.** It is the only pre-existing baseline, so it is the one comparison that
is not self-referential — the service is new, the cases and the recorded result are not.

**Limits.** n=15. See the interval table.

## 5. `tests/fixtures/eval_suite.py` — the 30-question graded battery

**What.** Hand-written, 27 cases / 30 questions, all three types, ordered trivial to known-hard: negation,
absence of evidence, resolved-vs-open, distractors, 2/4/8/16-way choice, 2/3/5/10-level scores, deliberate
ambiguity, and multi-rule policy composition.

**What it showed.** Combined with the baseline pack: so1 **42/45**, Jev **43/45**. Two of so1's three
misses are the deliberate-ambiguity cases, which **Jev also fails**.

**Why this was the right dataset.** The baseline pack is 8 choice / 6 noul / 1 score — it barely exercises
score, and has no negation or ambiguity probes. This fills those gaps.

**Limits.** Written by the same process that built the service, which is the sharpest bias risk here. The
mitigation is that both systems see identical inputs and are graded by identical code, so the *relative*
result stands even if the absolute number is optimistic. The ambiguity cases in particular use a
threshold we invented (confidence < 0.5) that the reference implementation also fails, so they measure a
shared property rather than a so1 defect.

## 6. `scripts/bench_scaling.py` pools — 16 easy + 8 hard questions

**What.** Two question pools over `build_thread` states, swept across 500/1500/3000/6500 tokens and
1/2/4/8/16 questions.

**What it showed.** On the easy pool both systems are **100% at every size**, so long context alone does
not break accuracy — which is itself the finding. On the hard pool so1 falls to 38-50% beyond 500 tokens
while Jev holds 75-100%.

**Why two pools.** A saturated pool gives a clean latency signal with accuracy held constant; a
discriminating pool moves accuracy. Mixing them would confound the two.

**Limits.** The hard pool is 8 questions, so each point is coarse. Experiment 9 in `EXPERIMENTS.md`
supersedes the "degrades past a threshold" reading: the real behaviour is instability, not decay.

## 7. `scripts/bench_complex.py` — one realistic 12-question request

1.6 KB structured state (account records, 4-rule policy, 6-message thread), 12 questions. so1 **10/12**,
Jev **12/12**. Both misses were refund eligibility, traced in experiment 3 to state scope, not arithmetic.

## 9. Public benchmarks with real gold labels - the only unbiased measurement

**What.** Two public datasets pulled live from the HuggingFace dataset server by
`scripts/bench_public.py`. Neither the inputs nor the labels came from us.

- **BoolQ** (`google/boolq`, validation, n=300) - yes/no reading comprehension over a passage. Maps
  directly onto `noul`.
- **SST-5** (`SetFit/sst5`, test, n=250) - five-level sentiment. Maps directly onto `score` with five
  ordinal levels.

**What it showed.**

| | so1 (gemma4-e4b) | jev-1.13.0 |
|---|---|---|
| **BoolQ** accuracy | 248/300 = **82.7%** [78.0, 86.5] | 283/300 = **94.3%** [91.1, 96.4] |
| BoolQ ECE / Brier | 0.151 / 0.159 | **0.039 / 0.051** |
| BoolQ McNemar | 0 in our favour, 35 in Jev's | **p < 0.0001, significant** |
| **SST-5** accuracy | 140/250 = **56.0%** [49.8, 62.0] | 151/250 = **60.4%** [54.2, 66.3] |
| SST-5 mean abs error | 0.522 levels | 0.448 levels |
| SST-5 within 1 level | 85.6% | 92.4% |
| SST-5 ECE / Brier | 0.364 / 0.363 | **0.187 / 0.265** |
| SST-5 McNemar | 24 ours, 35 Jev's | p = 0.19, not significant |

**Why this matters more than everything above it.** On our own synthetic battery the accuracy gap was
42/45 vs 43/45, McNemar p = 1.00 - "not significantly different". On BoolQ, with someone else's data and
someone else's labels, the gap is **11.6 points and overwhelmingly significant**, and it is perfectly
one-sided: there is not a single item Jev got wrong that we got right. That is the bias in self-authored
evaluation showing up exactly where it was predicted to.

**The nuance.** The gap is primitive-dependent. On `score` (SST-5) the two are statistically
indistinguishable on accuracy, and both sit near the practical ceiling for zero-shot 5-class sentiment.
The large, certain gap is on `noul`. That is consistent with everything else we measured: noul is where
our calibration is worst, where temperature wants to flatten us most, and where the failure modes in
experiments 3 and 9 live.

**Calibration is the clearest and most consistent difference.** Jev's ECE is ~4x better on BoolQ and ~2x
better on SST-5. This is the one claim TypeSafe makes that our numbers fully corroborate, on both
primitives, on third-party data.

**Limits.** BoolQ and SST-5 are both general-domain and neither resembles a support-ticket workload.
n=300 and n=250 give roughly +/-5-6pp. Run 1000+ items on domain data before any production decision.

## 8. `archive/compare_20260922_004749.json` — 109 items, two models, two readouts

Pre-existing. The most statistically useful set we have, and the only one comparing model sizes:

| model | readout | accuracy |
|---|---|---|
| 26B-A4B | logit | 108/109 (99%) |
| 26B-A4B | generation | 108/109 (99%) |
| E4B | logit | 99/109 (91%) |
| E4B | generation | 99/109 (91%) |

Two conclusions. The logprob readout costs **nothing** in accuracy versus letting the model write its
answer — which is the core premise of this service, independently confirmed. And **26B-A4B beats E4B by
8 points on identical items**, which is the strongest available evidence that our remaining accuracy gap
is model capacity.

## What the numbers can and cannot support

95% Wilson intervals:

| claim | value | 95% CI | width |
|---|---|---|---|
| so1 head-to-head | 42/45 = 93.3% | [82.1, 97.7] | 15.6pp |
| jev head-to-head | 43/45 = 95.6% | [85.2, 98.8] | 13.6pp |
| so1 baseline pack | 14/15 = 93.3% | [70.2, 98.8] | 28.6pp |
| so1 complex case | 10/12 = 83.3% | [55.2, 95.3] | 40.1pp |
| E4B archived | 99/109 = 90.8% | [83.9, 94.9] | 11.0pp |
| 26B archived | 108/109 = 99.1% | [95.0, 99.8] | 4.9pp |

**On the synthetic battery the gap is not statistically significant** - McNemar on the 45 paired items
gives one discordant pair, p = 1.00. **On public data it is.** BoolQ (n=300) gives 35 discordant pairs,
all in Jev's favour, p < 0.0001, an 11.6 point gap. Where the two disagree, believe the public benchmark:
the synthetic set was written by the same process that built the service.

**The E4B-vs-26B gap is significant.** Nine discordant pairs, all one way, p = 0.004.

**What is solid regardless of n:** the contract findings (deterministic, not statistical), the confidence
formulas (fitted to 0.0085 MAE), the qualitative failure mode in experiments 3 and 9 (reproduced across
many state sizes with a swing from 0.014 to 0.958), and the latency measurements (many repeats, low
within-session variance).

**What we would need for a defensible accuracy claim:** a few hundred items, drawn from real traffic,
labelled by someone who did not write the service, with a held-out split. Until then treat every accuracy
figure here as directional.
